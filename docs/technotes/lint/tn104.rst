:og:description: TN104 fires when a technote declares a DOI that is not syntactically a DOI, so the citation and CITATION.cff that are generated from it would be wrong.

#######################
doi-well-formed (TN104)
#######################

.. list-table::
   :header-rows: 1

   * - Group
     - Default severity
   * - Metadata
     - Error

A technote's ``[technote] doi`` is the identifier every citation of the document resolves through: the "Citing this document" section, the BibTeX entry, the :file:`CITATION.cff` file, and the DOI metadata registered with DataCite all read it.
This rule checks that the declared value is syntactically a DOI — the ``10.NNNN/suffix`` form, optionally written as a ``https://doi.org/`` URL or with a ``doi:`` prefix.

The check is entirely offline: it validates the *shape* of the identifier, not whether it is registered or what it resolves to.

A technote that declares **no** DOI is not flagged.
A DOI is minted when a technote is released, so most technotes go without one for most of their lives, and an absent ``doi`` field is normal.

Example of a failing technote
=============================

.. code-block:: toml
   :caption: technote.toml

   [technote]
   id = "SQR-000"
   doi = "10.71929"

.. code-block:: text

   [TN104] technote.toml does not declare a valid DOI: Not a DOI (10.71929). A DOI looks like 10.5281/zenodo.10385500, and may also be given as a https://doi.org/ URL.

How to fix it
=============

Write the DOI in one of the accepted spellings.
All three of these declare the same DOI:

.. code-block:: toml
   :caption: technote.toml

   [technote]
   doi = "10.71929/rubin/2570308"

.. code-block:: toml
   :caption: technote.toml

   [technote]
   doi = "https://doi.org/10.71929/rubin/2570308"

.. code-block:: toml
   :caption: technote.toml

   [technote]
   doi = "doi:10.71929/rubin/2570308"

Documenteer normalizes whichever spelling you use to the bare ``10.NNNN/suffix`` form wherever it displays or exports the DOI, and shows it as a resolvable ``https://doi.org/`` URL in citations.

The usual causes of a finding are a DOI that lost its suffix (``10.71929`` with no ``/…`` after it), a DOI pasted with surrounding text, and a Zenodo or DataCite *record* URL pasted in place of the DOI itself.
If the technote does not have a DOI yet, remove the ``doi`` field rather than leaving a placeholder — an absent DOI is not a finding.
