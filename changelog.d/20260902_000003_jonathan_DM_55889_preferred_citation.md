### New features

- A `[[project.citations]]` entry in a user guide can now set `preferred = true`, which says the site asks readers to use that citation without claiming the site is that DOI's landing page. `self` is narrowed to the landing-page claim alone — it is what drives the Highwire `citation_doi` and Dublin Core `DC.identifier` meta tags and the subject of the site-wide schema.org JSON-LD block — while `preferred` is what an argument-less `citation-card` renders and what `in_footer` defaults to true for. At most one entry may set each, and `preferred` defaults to the `self` entry, so a site that publishes its own DOI states neither field twice and every existing configuration is unchanged. The two part ways for a repository whose `CITATION.cff` declares a `preferred-citation`: that paper is published elsewhere and its landing page is its publisher's, so the entry is marked `preferred` rather than `self`.

### Other changes

- A user guide that declares citations but marks none of them `self` now emits a site-wide JSON-LD block whose subject is the site itself — a schema.org `WebSite` carrying the site's title and base URL and no identifier at all, since such a site publishes no DOI of its own — instead of a bare `@graph` of records. The declared works reach that subject under the same two relations, and in the same shapes, as they reach a `self` citation: an entry that claims a `page` is named in `hasPart` by reference alone, and a work the footer shows is stated in full under `citation`. Only the subject differs, so a consumer reads the block the same way whether or not the site publishes a DOI.
