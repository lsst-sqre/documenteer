### Bug fixes

- `documenteer.ext.linkcheckservice` no longer tells technote authors to edit a `documenteer.toml` their project does not have. The extension is loaded by both `documenteer.conf.guide` and `documenteer.conf.technote`, but four of its build-log messages hardcoded `documenteer.toml` or a TOML key that exists nowhere in a technote's configuration. Each message is now worded for the kind of project being built. A technote missing an origin base URL is pointed at `[technote] canonical_url` or `[technote] id` in `technote.toml` (its origin is derived from those, never authored directly). Its strict-mode messages name `documenteer_linkcheck_strict = True` in `conf.py`, and the message announcing the fallback to Sphinx's built-in link checker on a build without an `OOK_TOKEN` names `documenteer_linkcheck_use_service = False` in `conf.py` — `technote.toml`'s schema belongs to the technote package, not to Documenteer. A guide's messages name the same keys as before, each now with the `documenteer.toml` they live in. A project configured from `conf.py` alone is pointed at the `documenteer_linkcheck_origin_base_url`, `documenteer_linkcheck_strict`, and `documenteer_linkcheck_use_service` Sphinx config values, naming no file it does not have. Only the wording changed: the same messages fire in the same branches at the same levels, and every build's exit status is exactly as before.

### Other changes

- The technote configuration documentation now documents the link-check settings a technote overrides in `conf.py` — `documenteer_linkcheck_strict`, `documenteer_linkcheck_use_service`, `documenteer_linkcheck_service_url`, and `documenteer_linkcheck_poll_budget` — so the corrected build-log messages point at a documented knob. The new section also explains why these are `conf.py` values rather than `technote.toml` keys, and that a technote's origin base URL is derived from `[technote] canonical_url` or `[technote] id` rather than set directly.
- The `documenteer.toml` reference is now scoped to user guides alone: its `[sphinx.linkcheck]` section no longer carries an aside about how a technote configures the same builder. A technote does not read `documenteer.toml`, so that material belongs with the rest of the technote configuration documentation — where a technote author is already looking — rather than in the schema reference for a file their project does not have.
