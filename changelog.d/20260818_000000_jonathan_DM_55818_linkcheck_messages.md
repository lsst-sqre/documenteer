### Bug fixes

- `documenteer.ext.linkcheckservice` no longer tells technote authors to edit a `documenteer.toml` their project does not have. The extension is loaded by both `documenteer.conf.guide` and `documenteer.conf.technote`, but three of its build-log messages hardcoded `documenteer.toml` and named TOML keys that exist nowhere in a technote's configuration. Each message is now worded for the kind of project being built. A technote missing an origin base URL is pointed at `[technote] canonical_url` or `[technote] id` in `technote.toml` (its origin is derived from those, never authored directly), and its strict-mode messages name `documenteer_linkcheck_strict = True` in `conf.py` — `technote.toml`'s schema belongs to the technote package, not to Documenteer. A guide's messages are unchanged. A project configured from `conf.py` alone is pointed at the `documenteer_linkcheck_origin_base_url` and `documenteer_linkcheck_strict` Sphinx config values, naming no file it does not have. Only the wording changed: the same messages fire in the same branches at the same levels, and every build's exit status is exactly as before.
