### New features

- `documenteer technote sync-authors` now repairs an author's `internal_id` from the ORCID their `technote.toml` entry declares. An entry whose `internal_id` is not in the Rubin author database has it rewritten in place — the corrected ID replaces the wrong one in that entry rather than being appended as a second author — and an entry with no `internal_id` at all has one filled in. ORCID is globally unique and author-supplied, so the lookup identifies the author exactly. The report names what changed, for example `- R. Lynne Jones (lynnej → jonesrl, matched by ORCID)`. This makes the command the literal fix that a `technote lint` TN101 or TN102 finding names for an author who declares an ORCID, rather than something to run after hand-editing the ID; a TN101 suggestion matched by ORCID now says so, ending `Run 'documenteer technote sync-authors' to add it.`

### Bug fixes

- `documenteer technote sync-authors` no longer abandons the whole run at the first author it cannot resolve. Previously an `internal_id` missing from the Rubin author database escaped as an unhandled exception, printing a traceback and leaving `technote.toml` unwritten, so one unknown author cost every other author their update. Such an author is now reported as a warning and left exactly as declared, every other author is still synchronized and written, and the command exits non-zero. Every other way one entry can fail is reported the same way, including a record the author database returns malformed. A repair whose ID another entry already declares is reported rather than written, so the command never turns a duplicated author into two identical entries.
