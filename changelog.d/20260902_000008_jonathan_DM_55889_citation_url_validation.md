### Other changes

- A `[[project.citations]]` entry's `url` in a user guide is now validated when the configuration loads: it is stripped, and a blank one or one that is not an absolute `http` or `https` URL fails the build with a message naming the field. A blank string previously satisfied the check that an entry is locatable — it is truthy — and then reduced to nothing where the citation was composed, yielding a plain-text citation with no link, a BibTeX entry with neither `url` nor `doi`, and a JSON-LD node with no `@id`; a scheme-less one became a link relative to whichever page carried the citation, and a relative IRI as that node's `@id`. A `CITATION.cff` file's `url` and `repository-code` are validated the same way where the file is read, so a landing page lands in the same shape whichever source states it.
