### New features

- Added a `documenteer technote validate` command that checks a technote's metadata and structure before a build. It verifies that `technote.toml` exists (`TN004`), is valid TOML (`TN005`), and conforms to the technote schema (`TN001`), and that `requirements.txt` declares `documenteer[technote]` (`TN002`) without pinning Sphinx separately (`TN003`); that every author declares a resolvable `internal_id` in the Rubin author database — flagging authors missing an ID (`TN101`), IDs absent from or malformed in the database (`TN102`, an error), and an unreachable database (`TN103`, a transport-only warning); and that the content declares an abstract via the abstract directive (`TN201`) rather than an ordinary section heading (`TN202`), reporting a content file that cannot be parsed (for example a corrupt notebook) as `TN203`. An abstract directive that is present but has no body is its own check, `TN204`, whose finding locates the directive as `file:line` — the common cause is abstract text left unindented under `.. abstract::`, which reStructuredText reads as an empty directive, so the page publishes an empty abstract and an empty `og:description` while the author sees a directive that looks fine. `TN202` locates its heading the same way. The abstract scan matches directive names in any letter case (docutils lowercases them), accepts an abstract written on the `.. abstract::` marker line itself, and resolves `.. include::` and `` ```{include} `` directives one level deep so an abstract factored into another file is still found. Each finding is prefixed with a stable linter-style code so a bad technote is reported as a triageable finding rather than a traceback, and `--strict/-s` promotes warnings to errors so CI can fail on them. An unparseable `technote.toml` no longer hides the rest of the report: only the author checks (`TN1xx`), which need the parsed metadata, are skipped, while the `requirements.txt` and content checks still run. When a `TN001` schema failure comes from a historical author-name form — `name = { name = "Full Name" }` (removed in technote 0.5) or `name = { given_names = "...", family_names = "..." }` (renamed in 2023) — the finding names the legacy form, shows the modern `name = { given = "...", family = "..." }` replacement, and points at `documenteer technote migrate`. A missing content file is reported as its own structural check, `TN006`, rather than as a missing abstract (`TN201`). An author `internal_id` that is missing (`TN101`) or unknown (`TN102`) is no longer a dead end: the finding names the ID the author probably wants — `Did you mean 'alsayyady' (matched by ORCID)?` — by searching the Rubin author database for their name and accepting a match only on a matching ORCID or a single near-exact name match, so an ambiguous search or a failed lookup silently leaves the plain message. Technote-series repositories that are not Sphinx projects — no `index.{rst,md,ipynb}` and no `conf.py`, built through the shared technote CI with a custom build command — are validated for their `technote.toml` alone: the `requirements.txt` checks, content checks, and `TN006` are skipped, so a healthy non-Sphinx technote passes.
