### New features

- Added a `documenteer technote validate` command that checks a technote's metadata and structure before a build. It verifies that `technote.toml` exists (`TN004`), is valid TOML (`TN005`), and conforms to the technote schema (`TN001`), and that `requirements.txt` declares `documenteer[technote]` (`TN002`) without pinning Sphinx separately (`TN003`); that every author declares a resolvable `internal_id` in the Rubin author database — flagging authors missing an ID (`TN101`), IDs absent from or malformed in the database (`TN102`, an error), and an unreachable database (`TN103`, a transport-only warning); and that the content declares a non-empty abstract via the abstract directive (`TN201`) rather than an ordinary section heading (`TN202`), reporting a content file that cannot be parsed (for example a corrupt notebook) as `TN203`. Each finding is prefixed with a stable linter-style code so a bad technote is reported as a triageable finding rather than a traceback, and `--strict/-s` promotes warnings to errors so CI can fail on them. An unparseable `technote.toml` no longer hides the rest of the report: only the author checks (`TN1xx`), which need the parsed metadata, are skipped, while the `requirements.txt` and content checks still run. When a `TN001` schema failure comes from a historical author-name form — `name = { name = "Full Name" }` (removed in technote 0.5) or `name = { given_names = "...", family_names = "..." }` (renamed in 2023) — the finding names the legacy form, shows the modern `name = { given = "...", family = "..." }` replacement, and points at `documenteer technote migrate`.
