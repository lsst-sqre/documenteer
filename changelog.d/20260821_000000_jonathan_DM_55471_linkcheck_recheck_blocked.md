### New features

- The link-check builder now rechecks bot-blocked URLs from the build's own vantage point and merges what it observes into that same build's report. Ook reports a URL as `blocked` when its requests trip a site's bot-protection edge (typically a Cloudflare `403`), which it can't distinguish from a URL refusing everyone. A documentation build usually runs somewhere the same site is happy to serve, so it can often settle what the service couldn't: exactly the blocked URLs are rechecked, sequentially and with a politeness delay, sending the same request Sphinx's built-in `linkcheck` builder would send (its browser-prefixed `User-Agent` and `Accept` header, HEAD then a streamed GET, redirects captured). A URL the build resolves is reported `ok` — or `redirected`, if it works only through a permanent redirect — and its bot-protection caveat clears; a URL the build definitively fails to reach is reported `broken` with the build's own evidence; a URL blocked from the build's vantage point too keeps its caveat and the service's evidence untouched. The `linkcheck.json` artifact carries the merged view, with each result the build rechecked for itself flagged `locally_rechecked`. Set `[sphinx.linkcheck] recheck_blocked = false` in `documenteer.toml` (or `documenteer_linkcheck_recheck_blocked = False` in a technote's `conf.py`) to skip the recheck and report the service's verdict as-is.
