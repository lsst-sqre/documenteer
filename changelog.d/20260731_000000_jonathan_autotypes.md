### New features

- New `documenteer.ext.autotypes` extension (enabled automatically by the user-guide preset) that bridges gaps in the autodoc/automodapi ecosystem for modern Python typing constructs:

  - PEP 695 `type` aliases are documented as proper `py:type` objects on Sphinx 8 (backporting the `autotype` documenter that Sphinx 9 provides natively), rendering `type Name = value` with the docstring written below the `type` statement — which Sphinx 9's native support doesn't pick up either. sphinx-automodapi generates the `autotype` stub pages automatically.
  - `Annotated` aliases (`X = Annotated[...]`) now get automodapi stub pages (previously listed in summary tables but skipped by stub generation because their `__module__` is `typing`), and show the docstring below their assignment instead of `typing.Annotated`'s own docstring — even when documented from a public re-export location.
  - A `missing-reference` handler resolves references that the autodoc ecosystem emits under names that don't match a documented target: role mismatches locally and against intersphinx inventories (e.g. a `py:data` reference to `typing.Union`), private-module paths for re-exported objects (`pkg._impl.Thing` → the documented `pkg.Thing`, `h5py._hl.files.File` → `h5py.File`), bare names from field annotations, class- and module-relative references, parameterized references (`Model[Any]`), references to modules documented with `automodapi::` and `:no-main-docstr:` (which otherwise have no `py:module` target), and PEP 695 scoped type parameters that sphinx-autodoc-typehints qualifies with a bogus `typing.` prefix (`class C[P: Base]` emitting `typing.P`, which no member of `typing` matches). References to objects that never have targets — TypeVars, PEP 695 scoped type parameters, undocumented aliases, dunder attributes in rendered alias values, importable objects from external packages absent from every intersphinx inventory (such as pydantic, which publishes none), and targets mangled by a leaked `repr()` (autodoc-pydantic renders `Annotated` field metadata such as lambdas and enum members into cross-reference targets that could never be dotted Python names) — degrade to unlinked literal text instead of nitpick warnings. A bare name that the page's own module can't import is resolved as a last resort through the MRO of the class it was rendered inside, which catches docstrings inherited from external base classes: a Pydantic model documented with `:inherited-members:` shows `pydantic.BaseModel.model_config`'s docstring and its bare `ConfigDict` reference, once per model page. Unresolvable references that point at real mistakes still warn.
  - On Sphinx 9, sphinx-automodapi's object classification is patched to consult third-party autodoc documenters again (Sphinx 9's autodoc rewrite removed the registry API automodapi used), restoring `autopydantic_model` stubs for Pydantic models instead of generic `autoclass` stubs that document every inherited `BaseModel` member with thousands of nitpick warnings. sphinx-click's `mock` import, which Sphinx 9 can leave pointing at a module instead of the context manager (`TypeError: 'module' object is not callable` on every `click` directive), is repaired as well.

  The extension is a package of three sub-extensions, split by problem domain: `documenteer.ext.autotypes.documenters` (how autodoc renders typing constructs), `documenteer.ext.autotypes.compat` (temporary shims for sphinx-automodapi and sphinx-click, which retire as those upstreams ship fixes), and `documenteer.ext.autotypes.xrefs` (the cross-reference resolution policy). Enabling `documenteer.ext.autotypes` enables all three; each sub-extension can also be enabled individually by name.

  In a trial against the lsst.images documentation, this cut nitpicky-build warnings from 463 to 18 on Sphinx 8 (6,394 to 37 on Sphinx 9) while reducing its `nitpick_ignore` configuration from 30 entries to a handful of genuinely-external ones, with every remaining warning pointing at a real documentation gap.
