### Backwards-incompatible changes

- The `technote` extra now requires technote 0.12, pinned as `technote>=0.12.0a1,<0.13.0`: the floor is the 0.12.0a1 pre-release, which is where these changes landed, and it rises to `>=0.12.0` once that release is final. When `[technote] date_updated` is not set in `technote.toml`, that release defaults it to the committer date of the checked-out commit rather than the build clock (`SOURCE_DATE_EPOCH` takes precedence, and the clock is used only outside a git repository), so a technote's citation date is reproducible and no longer changes with each rebuild. technote 0.12 also reports `technote.toml` validation errors field by field in the file's own vocabulary, the same format Documenteer uses for `documenteer.toml`.
