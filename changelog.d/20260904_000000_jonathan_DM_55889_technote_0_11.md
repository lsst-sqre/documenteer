### Backwards-incompatible changes

- technote 0.11.0 resolves a technote's title from the document's H1 at the end of Sphinx's read phase rather than only in the HTML builder, and owns the `[technote.lint]` table's schema. It also *renames* the Highwire date tag a technote emits, from `citation_date` to `citation_publication_date` — the name Documenteer already emits for user guides, and the one Google Scholar's inclusion guidelines specify. The old name is gone rather than duplicated, so anything that scrapes `citation_date` off a Rubin technote stops finding a date and needs updating. Documenteer's `technote` extra requires technote 0.12 or later, so every technote it builds behaves this way.
- `documenteer technote lint` no longer reports a malformed `[technote.lint]` table as TN007. technote validates the table's shape when it parses `technote.toml`, so an `ignore` that is not an array, an entry that is not a string, or a code that is not an uppercase prefix and a number is reported as TN001, once, and nothing is read from a table technote rejects. TN007 keeps reporting a well-formed code that names no rule. Codes in the file are matched exactly as technote accepts them (`TN105`, not `tn105`); `--ignore` on the command line still folds case.
