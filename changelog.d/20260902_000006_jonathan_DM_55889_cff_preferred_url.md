### New features

- A `[[project.citations]]` entry in a user guide can now set `cff_preferred = false`, which reads the *top-level* record of its `cff` file — the software or dataset the repository itself is — instead of the `preferred-citation` the file declares. It is the only way to cite a repository whose `CITATION.cff` prefers the paper that describes it, and a site can cite both by declaring two entries against the same file. `cff_preferred` chooses which record of a file is read and is unrelated to `preferred`, which chooses the citation the site asks readers to use; an entry that sets `cff_preferred` without `cff` is rejected.

- A `[[project.citations]]` entry can now set `url`, the work's landing page, and an entry is locatable by a URL as well as by a DOI: every entry but `self` may declare a URL and no DOI, which is how a package or a dataset that has never been deposited is cited. A `cff` file supplies the URL from its `url`, or from its `repository-code` when it states no landing page. Such a citation renders as plain text ending in that URL, as BibTeX with a `url` field and no `doi`, and as a schema.org node identified by the URL and carrying no `identifier` block. The `self` entry still requires a DOI, since it is the claim that this site is a DOI's landing page, and the error an entry with neither raises now names both fields.
