### Backwards-incompatible changes

- `documenteer technote sync-cff` no longer dates a citation from `technote.date_created`. That field is the day a technote was *started*, not the day it was released, and since most technotes never declare `date_updated`, the old fallback silently dated nearly every generated `CITATION.cff` to a day nothing was published on. A technote that declares no `date_updated` now generates a file with no `date-released` at all — the Citation File Format requires the field at neither level — and the command says once why, in the style of the existing missing-title warning. A technote repository that wants its citation dated should declare `date_updated` in the `[technote]` table; one that already does is unaffected, except that its `CITATION.cff` needs a re-sync for the change below.

### Other changes

- The `CITATION.cff` that `documenteer technote sync-cff` generates now mirrors the technote's `doi` and `date-released` onto the file's top-level record, alongside the `url` and `repository-code` already there. Tools that cite the top level rather than the `preferred-citation` — cffconvert and Zenodo's GitHub integration among them — were producing an undated, DOI-less citation of a technote that has both.
