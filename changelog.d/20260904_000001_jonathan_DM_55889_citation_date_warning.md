### New features

- A user guide whose `[[project.citations]]` entry states no publication date — and whose `cff` file supplies none either — now says so at build time instead of quietly citing the work undated. Each such entry emits one `documenteer.citation_date` warning naming the entry (by its `label`, or by its title when it has none) and where the date belongs: the entry's own `date` field, and, for an entry sourced from a `CITATION.cff` file, `date-released` (or `year`) in the record it reads there — the file's `preferred-citation`, or its top-level record when `cff_preferred = false` selects that one. Naming the record matters, because a file whose top-level software record carries no date at all can sit above a dated `preferred-citation`. Rendering is unchanged, so a site with no date to give adds `documenteer.citation_date` to `suppress_warnings` and keeps its warnings-as-errors build green.
