### New features

- New `documenteer.storage.citationcff` module reads a repository's `CITATION.cff` file into the shared `documenteer.citations.Citation` object, so a Documenteer site can source a citation's bibliographic fields from the file a project already maintains for GitHub's "Cite this repository" button instead of restating them. A `preferred-citation` wins outright when present, mirroring what GitHub renders; person authors (`family-names`/`given-names`/`name-particle`/`orcid`/`affiliation`) and entity authors (`name`) both map to citation authors; the DOI is resolved from the `doi` field or from an `identifiers` entry of `type: doi`, as Zenodo-generated files write it; and the publication date is taken from `date-released`, `date-published`, or a bare `year` and `month`. A missing file raises `CitationCffNotFoundError` and an unparseable or uncitable one raises `CitationCffParseError` — both `CitationCffError`, and both naming the offending path so a build can report it as-is. This is the reader half of the CITATION.cff integration; the guide configuration that consumes it follows.
