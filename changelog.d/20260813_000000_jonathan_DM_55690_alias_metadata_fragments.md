### Bug fixes

- `documenteer.ext.autotypes` no longer warns about the reference targets Sphinx synthesizes out of a *type alias's own* `Annotated` value. Safir's `type IvoaIsoDatetime = Annotated[datetime, BeforeValidator(...), PlainSerializer(..., when_used="json")]` is the shape: Sphinx renders the alias's value onto its page (and into every signature the alias annotates), stringifying each dataclass metadata field, and then unparses the result into a reference per fragment — leaking `PydanticUndefined` (the repr of `BeforeValidator`'s sentinel default) and `json` (the unquoted string value of `when_used`) as nitpick warnings. The existing fragments rung could not cover them because it rebuilds the fragments of a documented *class's* metadata, while an alias page carries no `py:class` context at all. A module-scoped sibling index now rebuilds the fragments that the `Annotated` aliases of the reference's `py:module` context module render — both a PEP 695 `type` statement and an assignment-style `Annotated` alias — and degrades those names to unlinked literal text. Like its class-scoped sibling it resolves nothing and is consulted only after every resolution rung has already failed, so a name no alias of that module renders — a typo of a real fragment included — keeps warning, and a fragment of one module's alias does not degrade under another module's context.
