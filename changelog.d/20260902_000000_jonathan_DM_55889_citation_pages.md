### New features

- A `[[project.citations]]` entry in a user guide can now name the page inside the site that is its DOI's registered landing page, with `page = "<docname>"` or `page = "<docname>#<fragment>"`. That page — rather than every page of the site — carries the entry's DOI as its Highwire `citation_doi` and Dublin Core `DC.identifier` meta tags, and a schema.org JSON-LD block describing the work at the page's own URL. This is what a data release's documentation needs when each data product has a DOI of its own that resolves to the product's page. Several entries may claim one page as long as each names a different fragment, in which case the page emits a JSON-LD `@graph` of all of them and no single-valued meta tag; two entries naming the same docname and fragment fail the build. Pages no entry claims are unchanged, and a `page` naming a docname the project does not contain warns under `documenteer.citation_page` rather than failing the build.
