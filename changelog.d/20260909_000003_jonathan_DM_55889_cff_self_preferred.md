### Bug fixes

- A `[[project.citations]]` entry that sets `self = true` while citing the `preferred-citation` of its `CITATION.cff` file now fails the build with a configuration error naming the entry. A preferred citation is by construction a work *other* than the repository — the paper to cite instead of the software — so its landing page belongs to whoever published it, and `self` published every page of the site as that work's full text: its `citation_title`, `citation_author`, `citation_doi`, and `DC.identifier` meta tags, a `citation_fulltext_html_url` pointing at this site, and a `ScholarlyArticle` JSON-LD subject, all telling Google Scholar and Zotero the site is a paper that resolves to someone else's publisher. The error offers the three fixes: `preferred = true` in place of `self` to ask readers to cite that work, `cff_preferred = false` to make this site the landing page of the repository's own record, or an explicit `cff_preferred = true` alongside `self` for the site that really is that work's landing page — a paper whose `CITATION.cff` and documentation site are one repository — which the build accepts as a deliberate claim. An entry whose file declares no `preferred-citation` is unaffected, since its top-level record describes the repository itself.
