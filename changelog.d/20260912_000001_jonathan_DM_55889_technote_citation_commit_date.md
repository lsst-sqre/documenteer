### Backwards-incompatible changes

- A technote that declares no `[technote] date_updated` is now cited by the date of the commit it is published from, rather than cited undated. technote 0.12 resolves `date_updated` from the checked-out commit's committer date (`SOURCE_DATE_EPOCH` takes precedence, and the build clock is used only outside a Git repository), and Documenteer now composes the citation from that resolved value rather than from the declared value alone. Every dated surface on the page therefore states one reproducible date: the sidebar's "Updated" line, the `citation_publication_date` metadata tag, the JSON-LD block, the **Cite** section's BibTeX `year` and `month`, and the citation at the end of the article. Rebuilding an unchanged commit composes exactly the same citation. A technote that declares `date_updated` is unaffected — declaring it is how to pin the citation to a fixed date instead of letting it follow the latest commit. `documenteer technote sync-cff` deliberately does *not* follow: it writes `date-released` from a declared `date_updated` only, so a checked-in `CITATION.cff` does not go stale on every content commit, and a file with no `date-released` is valid CFF 1.2.0.

- The `documenteer.citation_date` warning no longer fires for a technote, and `documenteer.ext.citationdate` is no longer loaded by the technote preset. There is no such thing as an undated technote any more, so the report has nothing left to say about one; a technote whose `conf.py` lists `documenteer.citation_date` in `suppress_warnings` can drop the entry. The warning is unchanged for user guides, whose `[[project.citations]]` entries can still state no date.

- `documenteer technote lint`'s **TN105** DataCite cross-check no longer treats an undeclared `date_updated` as drift. A technote whose registered title and authors match its record reports nothing at all when it declares no date. Where a finding exists for some other reason and the technote declares none, the finding now closes by saying when the record was issued, that the technote is dated by its publishing commit, and that declaring `date_updated` pins the citation to a fixed date — informational, in place of the instruction to "set `date_updated = 2016-05-24` to date the citation" it gave before.
