### Bug fixes

- A `documenteer.toml` that fails validation now reports what is wrong with the file rather than with the model behind it. The build error used to be pydantic's own rendering of a `ValidationError` — a `1 validation error for ConfigRoot` header, a dotted zero-based location such as `project.citations.1.date`, a `Value error,` prefix, a truncated dump of the rejected input, and a link to pydantic's error documentation — none of which names anything a documentation author wrote. Each problem is now one paragraph: an address in the file's own vocabulary (`[[project.citations]] entry #2, field date`, `[[project.citations]] entry #1 (label 'Object')`, `[project] title`, `[sphinx.intersphinx.projects] python`), followed by the sentence the validator raised, verbatim. Values pydantic rejects on its own — a missing table, a value of the wrong type, a value outside an enumeration — are reported the same way, with pydantic's short message and without its frame. A file with several problems reports them all at once, numbered and counted, so they can be fixed in one pass. The original `ValidationError` stays chained to the raised `ConfigError`, so the traceback Sphinx saves still holds everything needed to debug the model itself.

- A `documenteer.toml` that TOML itself cannot parse now fails with a configuration error naming the file and the line and column the parser stopped at, instead of escaping as a raw `TOMLDecodeError` and being reported by Sphinx as a programmable error in `conf.py`.
