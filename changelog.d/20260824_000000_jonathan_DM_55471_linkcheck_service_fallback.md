### New features

- A link-check service outage no longer stops a build from checking its links. When Ook is unreachable, or a check doesn't finish within the poll budget, the builder now falls back to Sphinx's built-in in-process `linkcheck` check — the same fallback a missing `OOK_TOKEN` already took — instead of skipping link checking for that build. The exit status then comes from that check's own results: broken links fail the build, a clean run exits 0. The cost is time rather than coverage, since the in-process check visits every link from the machine running the build with none of the service's caching or retry buffering. The service problem itself is reported at the `INFO` log level rather than as a warning, so a warnings-as-errors (`-W`) build — which every Rubin documentation build is, including Documenteer's own `docs-linkcheck` job — no longer fails simply for coinciding with an outage, as the old warning made it. Strict mode is unchanged: with `[sphinx.linkcheck] strict = true` in `documenteer.toml` (or `documenteer_linkcheck_strict = True` in a technote's `conf.py`) a service problem still fails the build outright, with no fallback, for projects that want an outage surfaced rather than substituted for.
