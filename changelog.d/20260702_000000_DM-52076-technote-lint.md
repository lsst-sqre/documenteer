### New features

- Added a `documenteer technote lint` command that checks a technote's metadata, structure, and content before a build. Each finding carries a stable rule code so a bad technote is reported as a triageable finding rather than a traceback, and `--strict/-s` promotes warnings to errors so CI can fail on them. Every rule has a landing page under [documenteer.lsst.io/technotes/lint](https://documenteer.lsst.io/technotes/lint/index.html) describing the rule, showing a failing technote, and walking through the fix; the report links to the page for each rule it fires. A code's prefix names the rule set it belongs to: `TN` rules check what any technote needs, and `R` rules check Rubin's conventions and services (its author database, its technote packaging). The rules:

  - Structure: `technote.toml` exists (`TN004`), is valid TOML (`TN005`), and conforms to the technote schema (`TN001`); a Sphinx technote has an `index.{rst,md,ipynb}` content file (`TN006`); and `requirements.txt` declares `documenteer[technote]` (`R002`) without pinning Sphinx separately (`R003`).
  - Authors: every author declares a resolvable `internal_id` in the Rubin author database — flagging authors missing an ID (`R101`), IDs absent from or malformed in the database (`R102`, an error), and an unreachable database (`R103`, a transport-only warning). A missing or unknown ID is not a dead end: the finding names the ID the author probably wants — `Did you mean 'alsayyady' (matched by ORCID)?` — by searching the author database for their name and accepting only a confident match (a matching ORCID, or a single near-exact name match); an ambiguous search or failed lookup silently leaves the plain message.
  - Content: the technote declares its abstract with the abstract directive (`TN201`) rather than an ordinary section heading (`TN202`), the content file can be parsed (`TN203`, for example a corrupt notebook), and the abstract directive has a body (`TN204`). `TN204` and `TN202` findings locate the problem as `file:line`; the common `TN204` cause is abstract text left unindented under `.. abstract::`, which reStructuredText reads as an empty directive, publishing an empty abstract and `og:description` while the source looks fine. The abstract scan matches directive names in any letter case (docutils lowercases them), accepts an abstract written on the `.. abstract::` marker line itself, and resolves `.. include::` and `` ```{include} `` directives one level deep so an abstract factored into another file is still found.

  An unparseable `technote.toml` no longer hides the rest of the report: only the author checks, which need the parsed metadata, are skipped. When a `TN001` schema failure comes from a historical author-name form — `name = { name = "Full Name" }` (removed in technote 0.5) or `name = { given_names = "...", family_names = "..." }` (renamed in 2023) — the finding names the legacy form, shows the modern `name = { given = "...", family = "..." }` replacement, and points at `documenteer technote migrate`. Technote-series repositories that are not Sphinx projects — no index content file and no `conf.py`, built through the shared technote CI with a custom build command — are linted for their `technote.toml` alone, so a healthy non-Sphinx technote passes.
